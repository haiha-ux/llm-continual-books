# llm-continual-books

Teach an open 7B LLM (Qwen2.5-7B-Instruct) three obscure public-domain books **in steps** and measure what it forgets.
Every result is a number produced by the scripts here; nothing is edited by hand.

**Status: finished for book 2, one seed. Book 3 was not run. The main result is negative: no method kept book 1 well while learning book 2 when the book-1 text is unavailable.**

## Problem and setting

"Add a book without forgetting the old one." The base model is first tested on each book (it should know almost
nothing). M1 = LoRA on book 1. Then book 2 is learned on top of M1 by three methods, while the book-1 text is treated
as *unavailable*:

| Method | What it does |
|---|---|
| `naive` | continue LoRA training on book 2 only |
| `kl` (generative self-replay + KL) | M1 writes its own book-style questions and answers them (plus teacher-written generic prompts answered by M1); while learning book 2, a KL term keeps the new model's outputs on these replay prompts close to M1 |
| `expert` (knowledge-insulated expert) | M1 is frozen; a new LoRA expert for book 2 sits on the upper layers behind a small learned gate that reads the question (idea borrowed from knowledge insulation in pi0.5); at inference the gate decides how much of the expert to apply |

Book 3 (naive and the best method) and a second seed are run only if time allows; they are listed in the table only if
they exist in `results/`.

## Metrics

* Book accuracy: short-answer questions written from the passages by an open Qwen teacher, filtered for
  answerability, 150 test questions per book, string-match scoring, greedy decoding (bf16 transformers).
* Book-1 retention: accuracy after each stage, and the fraction of the questions M1 answered correctly that are still
  answered correctly ("kept").
* General skills, on our own fixed subsets: GSM8K (200, 5-shot) and MMLU (500, 5-shot).
* Training cost in GPU-hours per book (wall clock including thermal rests).
* 95% bootstrap confidence intervals over questions. 8-gram overlap between training text and eval questions: 0
  (asserted in `scripts/build_data.py`, counts in `data/final/report.json`).

## Results

From `results/summary.md` (generated by `scripts/summarize.py`, plot `results/retention_vs_learning.png`). "Kept" is the
share of the 61 book-1 questions M1 answers correctly that are still correct.

| run | book 1 acc | book-1 kept | book 2 acc | GSM8K | MMLU |
|---|---|---|---|---|---|
| base | 0.7% | | 1.3% | 70.5% | 71.6% |
| M1 (book 1) | 40.7% | 61/61 | 2.7% | 59.0% | 71.8% |
| naive on book 2 | 6.0% | 8/61 | 36.7% | 54.5% | 69.2% |
| self-replay + KL | 23.3% | 32/61 | 35.3% | 60.0% | 70.4% |
| insulated expert, soft gate | 17.3% | 26/61 | 31.3% | 59.0% | 71.4% |

Naive training wipes book 1. KL on self-replay keeps about half of it at almost no cost to book 2. The soft gate of
the expert opened on book-1 questions too (mean gate 0.68 on book 1, 0.98 on book 2), so it kept less than KL.

**Hard router on the expert (`results/router_e1.json`, `results/raw/e2_*.json`).** The gate was replaced by a 0/1
decision from a linear probe on M1's hidden states, trained to tell book-2 questions from book-1-like questions that
M1 writes itself (no book-1 text needed).

* With the true label forcing the gate (oracle), book 1 is kept 61/61 and book 2 stays at 47/150. The expert and the
  loading path are fine; everything depends on the router.
* The best usable router sends 93% of book-2 questions to the expert but also 30% of book-1 questions (95% CI 23-38%),
  and under 1% of MMLU/GSM8K questions. End result: book 1 kept 45/61, book 2 45/150.
* A router trained on teacher questions written from the book-1 text drops the book-1 error to 11%, so the gap is
  mostly about style: the probe partly learns "M1 wrote this" rather than "this is about book 1". Removing style
  directions or restating M1's questions with the teacher only moved it from 37% to 30%.
* Two books on a similar subject (Arctic voyages) are the hard case. Unrelated questions are almost never routed.
* Chat-format MMLU/GSM8K answers are identical to M1 on 500/500 and 199/200. The few-shot skill evals of the router
  run were stopped by the thermal guard and are not reported.

## Reproduce

```
pip install -r requirements.txt            # plus a local Ollama with: ollama pull qwen2.5:7b-instruct
python -m pytest -q tests                  # unit tests
PYTHONPATH=src python scripts/smoke.py     # < 1 min plumbing check on a tiny random model
./run.sh gen 1,2,3                         # teacher data (resumable)
tools/pipeline.sh                          # build data -> base pre-test -> M1 -> naive / kl / expert -> summary
SEED=1 ./run.sh train configs/naive_b2.json out='"ckpt/naive_b2_s1"' name=naive_b2_s1   # another seed
```

Single master seed `SEED` (default 0). `run.sh` runs GPU jobs one at a time, niced, behind the shared GPU locks.

## Limitations (honest)

* Small books: 160k characters each (60-74 passages); questions are about fine details of obscure texts.
* String-match scoring undercounts paraphrased correct answers and is blind to partial credit.
* GSM8K/MMLU numbers are on our own small subsets, comparable only before/after.
* Part of the data was written by the bf16 teacher (book 1), part by a Q4-quantised teacher served by Ollama (rest);
  see [TEACHERS.md](TEACHERS.md). Same family and filters, not identical.
* One seed unless a second one is listed; CIs reflect question sampling only, not training variance.
* One machine (GB10, unified memory) that overheats: all loops rest 50% of the time and are paused by a thermostat,
  and a guard kills jobs at high temperature, so GPU-hours are wall-clock with rests and not comparable to a cooled GPU.

See [DATA.md](DATA.md) for sources, hashes and filtering.
